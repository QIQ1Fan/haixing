# haixing —— STM32F103C8T6 八路循迹小车

一个**能真的跑起来**的循迹小车工程：八路探头循迹 + 转向环 PID + 左右轮差速 +
OLED 按键调参（参数可掉电保存）+ 支撑脚舵机 + 串口自检。

* 主控：STM32F103C8T6（72MHz，HSE 8MHz × 9）
* 工程：Keil MDK（ARM Compiler 5.06 update 7），CubeMX 生成骨架 + 手写 BSP / 应用层
* 控制周期：10ms（100Hz），主循环软节拍

---

## 1. 硬件接线（和代码里的宏一一对应，改线只改 `Core/Inc/bsp_config.h`）

| 功能 | 引脚 | 配置 | 说明 |
|---|---|---|---|
| 左电机 PWM | PA6 | TIM3_CH1，20kHz | TB6612 PWMA |
| 右电机 PWM | PA7 | TIM3_CH2，20kHz | TB6612 PWMB |
| 左电机方向 | PB0 / PB1 | 推挽输出 | AIN1 / AIN2 |
| 右电机方向 | PB10 / PB11 | 推挽输出 | BIN1 / BIN2 |
| TB6612 使能 | PA4 | 推挽输出 | STBY，高 = 工作 |
| 左编码器 | PA0 / PA1 | TIM2 编码器模式 | 硬件四倍频 |
| 右编码器 | PB6 / PB7 | TIM4 编码器模式 | 硬件四倍频 |
| 八路循迹 | PA2 PA3 PA5 PA8 PA11 PA12 PB5 PB12 | 上拉输入 | 索引 0→7 对应车头从左到右 |
| 支撑脚舵机 | PB4 | 普通 GPIO 软件 PWM 50Hz | 见第 6 节 |
| 按键 确认/退出/加/减 | PB13 / PB14 / PB15 / PA15 | 上拉输入，按下读低 | 四个功能键 |
| 蜂鸣器 | PB3 | 推挽输出，**低电平触发** | |
| OLED SCL / SDA | PB8 / PB9 | 推挽输出，软件 I2C | SSD1306 128×64，地址 0x78 |
| 串口 | PA9 (TX) / PA10 (RX) | USART1，115200-8-N-1 | 调试 / 自检 / 调参 |
| SWD | PA13 / PA14 | 下载调试 | 不能动 |

**三个 JTAG 引脚的坑**：PA15 / PB3 / PB4 默认是 JTAG 的 JTDI / JTDO / NJTRST。
`HAL_MspInit()` 里的 `__HAL_AFIO_REMAP_SWJ_NOJTAG()` 把它们释放成普通 GPIO
（SWD 下载不受影响）。**删掉那一行，按键"减"、蜂鸣器、舵机会同时静默失效。**

**舵机供电**：舵机堵转电流可达 1A 以上，**必须独立 5V 供电并与单片机共地**，
绝不能从 STM32 的 3.3V 取电，否则会出现"一打角就复位"。

## 2. 软件分层

```
应用层  app_*      app_menu    OLED 调参界面 + 四按键
                   app_car     循迹控制律、状态机、丢线 / 堵转保护
                   app_leg     支撑脚舵机
                   app_param   所有可调参数 + Flash 掉电保存
驱动层  bsp_*      bsp_motor / bsp_servo / bsp_track / bsp_encoder / bsp_key
                   bsp_oled / bsp_uart / bsp_buzzer / bsp_gpio / bsp_pid / bsp_test
```

**参数总线**：`g_param`（在 `app_param.c`）是所有可调参数的唯一存放处。
`app_menu` 改它，`app_car` / `app_leg` **每个控制周期都重新读它**，
所以调参是"下一拍立即生效"的，不需要任何通知机制 —— 这也是能边跑边调的原因。

| 文件 | 作用 |
|---|---|
| `Core/Src/main.c` | 唯一的调度者：初始化顺序 + 10ms 主循环 |
| `Core/Inc/bsp_config.h` | ★ 硬件资源分配 + 所有编译期常量（引脚对不上只改这里） |
| `Core/Src/app_param.c` | ★ 出厂默认参数表 + 参数描述表（名字 / 步长 / 上下限） |
| `Core/Src/app_car.c` | ★ 循迹控制律（误差 → PID → 差速 → 保护） |
| `Core/Src/app_menu.c` | OLED 菜单：状态页 / 主菜单 / 参数列表 / 编辑 / 实时调参 |
| `Core/Src/bsp_pid.c` | 带 dt、抗积分饱和、微分低通的通用 PID |

## 3. 快速上手

1. Keil 打开 `MDK-ARM/haixing.uvprojx`，直接 Build（新增的源文件已经加进工程了）。
2. 下载，串口助手开 **115200-8-N-1**（串口里的中文提示需要把助手设成 **UTF-8**）。
3. 上电应该看到：蜂鸣器一声、OLED 显示状态页、串口打印启动横幅和参数表。
4. 先跑自检：串口敲 `?` 看菜单，按 `1`~`9` 逐项验硬件。建议顺序：
   2 串口 → 1 蜂鸣器 → 9 OLED → 3 舵机 → 6 编码器 → 7 循迹 → 8 按键 → 4/5 电机。
5. 硬件全绿之后：把车放到线上，OLED 菜单选 **START CAR**（或串口敲 `C`）就能跑。

## 4. OLED 按键操作

四个键的角色固定，状态页最后一页永远印着提示：

| 键 | 引脚 | 作用 |
|---|---|---|
| 确认 OK | PB13 | 进入 / 选定 / 确认 |
| 退出 BACK | PB14 | 返回上一级；**状态页且车在跑时 = 急停** |
| 加 + | PB15 | 光标上移 / 数值 + |
| 减 - | PA15 | 光标下移 / 数值 - |

长按 0.6 秒后进入连发，参数编辑和列表滚动都会自动加速。

界面结构：

```
状态页 ──OK──► 主菜单 ──┬── START / STOP CAR     启动 / 停止循迹
  ▲                     ├── TUNE PARAMS ──► 参数列表 ──OK──► 参数编辑
  │                     ├── SUPPORT LEG         支撑脚放下 / 收起
  └────BACK──────────── ├── SENSOR VIEW         8 路探头实时状态
                        ├── SAVE PARAMS         写进 Flash
                        ├── LOAD DEFAULT        恢复出厂值
                        └── INFO                版本信息

状态页 ──OK（车在跑）──► 实时调参页（车照跑，改完立刻生效，BACK 返回）
```

* **参数编辑**：`+` / `-` 按参数表里的步长调整，`OK` 确认，`BACK` 放弃本次修改。
* **实时调参**：跑车时按 `OK` 进入，`OK` 切换要调的参数，`+` / `-` 改值，
  `BACK` 回到状态页（**不会停车**）—— 这是整定 PID 最快的方式。
* 改完参数记得回主菜单 **SAVE PARAMS**，否则掉电就回到上一次保存的值。

## 6. 支撑脚舵机

* 舵机信号在 **PB4**，用 **TIM1 做时基 + 中断翻转引脚**的软件 PWM（50Hz）。
  为什么不用硬件 PWM：PB4 上唯一的定时器通道是 TIM3_CH1，而 TIM3 已经被电机
  PWM 占用，且 TIM3 的重映射是"整组生效"，一重映射电机就没波形了。
* 角度约定 **0°~180°**（500~2500us）。`app_leg.c` 让支撑脚**每 10ms 走 2°**，
  不会一步到位把机构顶坏。
* 两个位置（收起 / 放下）是**参数** `LEGUP` / `LEGDN`，必须在实车上标定：

  1. 菜单里选 `SUPPORT LEG` → `LEG DOWN`，把脚放下来
  2. 逐步调 `LEGDN`（参数列表里），直到车轮刚好离开地面
  3. **再回调 5~10°** 留余量 —— 舵机长期顶在死点会发热甚至烧掉
  4. 同样方法定 `LEGUP`，让脚完全收进车体、不刮地
  5. 回主菜单 `SAVE PARAMS`

**本阶段只做手动收放**。行驶中自动收放的逻辑属于后续阶段，
到时候只要在 `app_car` 的状态变化处调用 `APP_Leg_Up()` / `APP_Leg_Down()` 即可，
`app_leg.c` 不用改。

## 7. PID 整定（从默认值到能跑）

默认参数只是"能跑起来"的起点，务必按下面的顺序整定。
强烈建议用**实时调参页**边跑边调。

1. **先把 KI、KD 设成 0**，只留 KP，从默认 1200 开始：
   * 车在直道上画龙（左右摆）→ KP 太大，往小调
   * 车反应迟钝、入弯冲出去 → KP 太小，往大调
   * 目标：直道基本不摆，弯道能跟着线走（允许轻微滞后）
2. **加 KD**（默认 180）：它是"提前量"，慢慢加大直到摆动明显收敛。
   * KD 太大 → 高频抖动、电机嗡嗡叫（探头是开关量，D 项对噪声很敏感）
3. **DEADZONE**（默认 0.08）：直道上车骑在两条探头之间来回跳时，
   加大一点就能压住这种无意义的抽动。
4. **BASESPD / TURNMAX**：基础速度和最大转向差速。
   速度快了循迹跟不上，就先降 BASESPD，找到"能稳定跑"的上限再谈别的。
5. **MINSPD**：弯道内侧轮的最低速度。设成 0 允许内轮反转（能更急地转弯但会顿）；
   设成 300 左右跑起来更顺。
6. **KI 一般保持 0**。循迹环是"跟着线走"，不是"消除稳态误差"，
   加了积分反而容易在弯道出口画龙。
7. 最后 `SAVE PARAMS`。

参数含义详见 `Core/Inc/app_param.h` 的结构体注释和 `Core/Src/app_param.c` 的默认值表。

## 8. 常见问题

| 现象 | 先查什么 |
|---|---|
| 车往反方向拐 | 菜单把 `STEERINV` 改成 1；若连前进都不对，把 MOTOR_L_INVERT / MOTOR_R_INVERT 同时改 1 |
| 一直循不到线 / 掩码不随位置变 | `SENSOR VIEW` 看原始掩码；不行就把 bsp_config.h 的 `TRACK_ACTIVE_LOW` 取反 |
| 按键"减"、蜂鸣器、舵机中有一个不工作 | `HAL_MspInit()` 里的 `SWJ_NOJTAG` 是不是被删了 |
| 舵机一打角单片机就复位 | 舵机没独立供电 / 没共地 |
| 屏幕全黑 | `OLED_I2C_ADDR` 改 0x7A 试试；调小 `OLED_I2C_DELAY_LOOPS`；检查 SCL/SDA 是否接反 |
| 转速读数明显不对 | 改 `ENC_PPR` / `ENC_GEAR_RATIO`；看串口打印的 `encoder dt` 是不是接近 10ms |
| 一上电就报警 STALL | 编码器线没接（这是设计好的：给电不转就报警）；或 `STALLms` 设得太小 |
| 保存参数后单片机不启动 | `PARAM_FLASH_PAGE_ADDR` 和程序代码重叠了，见 bsp_config.h 第 11 节 |

## 9. 设计上值得一提的几处

* **转速用实测 dt 换算**（`bsp_encoder.c`）：主循环被 OLED 刷屏拖到 20~40ms 时
  转速依然准确，而"写死 10ms"会让读数虚高好几倍。
* **OLED 只刷变化的页**（`bsp_oled.c`）：驱动内部保存了「屏幕上正显示着的那一帧」，
  刷新时逐页比对，只把有差异的页发出去。整屏 1024 字节走软件 I2C 要 40~50ms，
  只刷两三页只要 10~15ms，控制节拍不再被刷屏拖垮；而且界面代码可以放心地写成
  「清屏 + 整帧重画」，不用为了省 I2C 去搞增量绘制。
* **PID 带 dt + 条件积分抗饱和 + 微分低通**（`bsp_pid.c`）：
  这是"能边跑边调参"和"出弯不画龙"的前提。
* **丢线 / 十字 / 堵转三种路况各有明确策略**（`app_car.c`），
  每种只用一个参数控制，便于按赛道调整。
* **参数表驱动菜单**（`app_param.c`）：加一个参数只要在结构体和表里各加一行，
  菜单、限幅、串口打印全部自动跟上。
* **UART 输出一律 ASCII**（bsp_test.c 的新增部分）：armcc 会按主机区域设置解释
  源文件编码，某些中文字节对里恰好含 0x22 / 0x5C，会把字符串的引号"吃掉"，
  报出莫名其妙的 `missing closing quote`。注释里写中文没问题，字符串字面量别写。
